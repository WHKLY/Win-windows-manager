# 架构与平滑执行设计

## 目标边界

程序负责识别可管理的普通顶层窗口、生成确定性布局计划、在安全边界内执行几何变更，并保留一级可扩展的 Undo 历史。持续强制平铺、跨虚拟桌面管理和无需用户操作的配置持久化不在当前范围。

## 模块

| 文件 | 职责 |
|---|---|
| `main.ahk` | 进程入口、DPI 上下文、异常处理和启动模式 |
| `lib/Config.ahk` | INI 读取、默认值与范围校验 |
| `lib/WindowEvents.ahk` | `SetWinEventHook` 生命周期与轻量事件分发 |
| `lib/WindowRegistry.ahk` | HWND/PID 身份、顶层窗口过滤、显示器信息、锁定和交互状态 |
| `lib/Geometry.ahk` | 矩形、相交、边界、插值和 SmoothStep |
| `lib/LayoutPlanner.ahk` | 纯布局规划、评分、候选生成和确定性搜索 |
| `lib/LayoutExecutor.ahk` | 预检查、逐帧移动、最终读回和取消 |
| `lib/LayoutHistory.ahk` | 布局前几何快照 |
| `lib/DoubleTapGesture.ahk` | 双击 CapsLock 时间窗口识别 |
| `lib/Logger.ahk` | 不含窗口标题的结构化文本日志 |
| `lib/WindowManagerApp.ahk` | 触发控制、快捷键、托盘、自动事件队列和组件编排 |

规划器不调用 Win32，执行器不生成布局策略。

## 数据流

```text
WinEvent
  -> 事件初筛/去抖
  -> WindowRegistry
  -> LayoutPlanner
  -> LayoutExecutor
  -> 最终几何读回
  -> LayoutHistory
```

事件回调只记录候选并设置短定时器。新窗口去抖完成后，才执行窗口分类、规划与执行。执行期间 `Applying` 标志阻止新的布局事务重入。

双击 CapsLock 使用 `~CapsLock`，在按键按下时计数，并通过短定时器等待真实松开以过滤长按重复。`~` 保证单击 CapsLock 仍切换大小写；修饰键按住或两次间隔超过阈值时重置手势。

双击 CapsLock 触发专用手动布局入口：当前显示器上的最大化窗口会先异步恢复，非最大化全屏窗口通过 `allowFullscreen` 分类进入候选集合。随后所有合格窗口统一规划，Topmost 属性、焦点和 Z-order 不被修改。

## 自动布局

自动模式先生成方案 A：

- 只移动并调整新窗口；
- 旧窗口保持不动。

然后生成方案 B：

- 选择与新窗口初始区域最相关的、未锁定/未交互的最多 `MaxMovedExistingWindows` 个旧窗口；
- 新窗口和这些旧窗口共同搜索；
- 自动模式默认允许旧窗口在 0.80–1.20 倍原尺寸范围内缩放；
- 近期被用户调整不再影响候选资格或移动成本；
- 方案 B 必须达到收益阈值，且满足硬约束和扰动上限，才会覆盖方案 A。

质量函数对重叠、重要窗口遮挡、尺寸偏差、工作区覆盖、移动代价、间距偏差和中心偏差分别归一化。覆盖率通过窗口矩形并集计算；默认目标 90%，权重为 4，避免出现大面积无窗口区域。并列结果通过固定窗口顺序和候选顺序消除随机性。

## 手动布局

手动模式：

1. 收集目标显示器上的合格窗口。
2. 使用原布局和填充式规则网格作为两个起点；网格优先让窗口扩展到单元格范围。
3. 按锁定、新窗口、焦点和稳定排序处理窗口。
4. 对位置及 0.70–1.30 倍尺寸候选执行有限坐标下降。
5. 若最终分数没有改善，保留原布局并报告“当前布局已较优”。

求解预算由 `[Placement] SolverBudgetMs` 限制。超时返回当前最佳合法方案。

## 平滑执行

执行前：

- 校验目标窗口仍存在、PID 未变化；
- 校验窗口未进入交互状态；
- 校验显示器工作区没有显著变化；
- 捕获所有实际变更窗口的原始几何。

平滑开启时：

- 以当前几何为起点、计划目标为终点；
- 使用 `t²(3-2t)` 缓动；
- 约每 8 ms 对所有变更窗口一起调用 `SetWindowPos`，目标约 120 FPS；
- 使用 QPC 微秒时钟计算进度，并使用 Windows 高分辨率可等待定时器等待下一帧；
- 如果某一帧超时，不连续追赶多个过期帧，而是重新建立下一帧截止时间；
- 使用 `SWP_NOZORDER | SWP_NOACTIVATE | SWP_NOOWNERZORDER`；
- 不在帧循环中执行布局求解或读取窗口标题。

循环期间出现用户拖动/缩放或执行取消时，立即停止，不再强制跳到目标。最终提交前再次检查交互和显示器几何。最后读回每个窗口的实际位置/尺寸，最终容差为 2 px；否则标记失败或部分完成。

关闭平滑时，执行器直接提交与动画完全相同的目标几何。

## 历史与 Undo

只有实际改变了至少一个窗口几何的事务才写入历史。历史保存：

- HWND、PID 和身份键；
- 原始矩形；
- 所属显示器与工作区。

Undo 会跳过已关闭、PID 改变、显示器变化、超出当前工作区、已锁定或正在交互的窗口。恢复同样使用平滑执行器，并禁止触发新的自动布局。

## 安全设计

- 不调用 `WinActivate`、`SetForegroundWindow` 或修改 Z-order 作为布局步骤。
- 不默认提权。
- 不采集窗口正文或窗口标题到日志。
- 不静默写开机启动；托盘操作是显式入口。
- 所有外部窗口在采集、规划、执行之间都可能失效，因此身份与几何必须重复验证。
