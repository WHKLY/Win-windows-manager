# 分阶段实施计划

## 原则

- 每阶段结束时保持一个可启动、可关闭的版本。
- 先完成纯几何可测试能力，再接 Win32 执行层。
- 事件回调只做轻量筛选和入队，布局求解放入受控任务队列。
- 任何真实窗口变更前都先完成快照、预检查和可行性验证。
- 每阶段同步更新改动记录与验收记录，未实际执行的项目不得标记为通过。

## 阶段 A：基础运行、窗口识别与 DryRun

计划工作：

- 建立 AHK v2 入口、配置加载、日志、托盘、暂停/退出生命周期。
- 建立已存在窗口注册表与顶层窗口过滤。
- 接入 WinEvent hook，验证回调保持存活并在退出时释放。
- 实现显示器定位和 `DryRun` 规划输出，不执行真实窗口移动。
- 定义布局执行器和动画执行器的公共接口，为后续无跳变切换预留事务边界。

退出条件：

- 脚本可启动并安全退出，启动时不移动已有窗口。
- 能识别正常主窗口和主要系统窗口类别。
- 事件初筛没有明显重复处理，回调不执行长任务。
- DryRun 能输出可解释的计划和跳过原因。
- 阶段 A 相关检查与限制已写入验收记录。

## 阶段 B：单窗口放置与基础几何

计划工作：

- 实现矩形、工作区、边界、中心候选与窗口最小/最大尺寸约束。
- 新窗口按默认比例放置，验证应用接受的实际几何。
- 支持单窗口手动放置和基础锁定分类。
- 实现单窗口平滑过渡和可关闭的即时跳转模式。
- 建立几何单元测试和真实窗口验证入口。

重点验收：

- T01、T02、T03、T13、T16。
- 平滑移动基线测试 S01-S03。
- 几何函数自动测试通过。
- 所有真实窗口测试有具体证据，失败项如实记录。

## 阶段 C：自动联合优化

计划工作：

- 构建方案 A（仅新窗口）和方案 B（新窗口 + 少量已有窗口）。
- 实现质量评分、归一化、收益阈值、扰动上限和确定性排序。
- 加入近期用户调整保护、交互取消和内部移动隔离。
- 多窗口布局按同步帧平滑过渡，并在用户交互或显示器变化时取消。
- 记录方案选择理由与关键指标。

重点验收：

- T04、T05、T11、T18、T26。
- S04-S05。
- 自动模式确实能够移动旧窗口，但不会为微弱收益频繁干扰。

## 阶段 D：手动全局重排、锁定与 Undo

计划工作：

- 实现当前显示器全局重排、所有显示器逐屏重排、快捷键和托盘入口。
- 手动模式在约束内调整已有窗口尺寸。
- 实现窗口锁定/解锁、交互保护、执行前快照和一级 Undo。
- 实现部分失败恢复、变更读回和撤销后的自动回放抑制。
- 保证 Undo 也经过同一平滑执行器，并可由用户交互中断。

重点验收：

- T06、T07、T08、T09、T10、T12、T23。
- 手动重排必须处理已有窗口集合，不能退化为单窗口居中。

## 阶段 E：兼容性、稳定性与交付

计划工作：

- 验证负坐标多屏、DPI 缩放、虚拟桌面、权限差异和特殊应用。
- 完成日志脱敏、配置范围检查、README 和已知限制。
- 执行第 8 节全部可执行测试，记录未测试项及原因。
- 汇总最终变更文件、验证证据、残余风险和后续 P1 候选。
- 使用 Ahk2Exe 构建 `dist/Win-windows-manager-v0.1.0.exe`，嵌入应用图标，记录校验值并完成可执行文件冒烟测试。

重点验收：

- T14、T15、T19、T20、T21、T22、T24、T25。
- 全量回归 T01-T26。
- Windows 11 + AutoHotkey v2 真机环境有可复现记录。

## 阶段记录格式

每阶段结束时在 `docs/records/change-log.md` 和 `docs/records/acceptance.md` 中至少记录：

- 阶段与日期。
- 修改文件及用途。
- 实际运行的命令或手动步骤。
- `Passed`、`Failed`、`Not tested` 的明确状态。
- 失败原因、证据位置和残余风险。
- 是否保持可启动、可暂停、可退出。
