# 文档索引与维护约定

`docs/` 用于保存需求、设计、实施计划、变更记录、验收报告和使用说明。功能源码、可执行文件和运行时数据不放入此目录。

## 目录

| 目录/文件 | 用途 |
|---|---|
| `requirements/` | 原始需求、需求基线、任务定义和待确认事项 |
| `plans/` | 分阶段实施计划、阶段入口与退出条件 |
| `records/` | 改动文件记录、测试证据、阶段验收和风险 |
| `guides/` | 架构说明、构建/测试说明和 Windows 手动测试计划 |
| `environment.md` | 开发、运行和测试环境快照 |

后续如确有必要，可增加：

- `design/`：出现需要长期保留的详细设计时再增加；当前架构说明在 `guides/architecture.md`。
- `adr/`：影响范围较大且需要长期保留原因的架构决策。

不预先创建空目录；出现真实文档需求时再添加。

## 文档规则

1. `requirements/original-spec-v2.md` 是用户提供的原始规格，保持内容不变。需求演进通过新文件和新版本表达。
2. `requirements/task-definition.md` 是开发时实际遵循的需求基线；若与原始规格存在差异，必须先记录并由用户确认。
3. 每个实施阶段开始时更新 `plans/implementation-plan.md` 的阶段状态，结束时补充实际结果。
4. 每次修改文件后，在 `records/change-log.md` 记录文件路径、修改目的和验证情况。
5. 每个阶段结束前更新 `records/acceptance.md`。状态仅使用 `Passed`、`Failed`、`Not tested`。
6. 测试记录必须包含日期、环境、具体操作或命令、预期结果、实际结果和证据。没有实际执行证据时不得写 `Passed`。
7. 文档使用 UTF-8；路径使用相对仓库根目录的写法；代码标识符、配置项和日志字段可以使用英文。
