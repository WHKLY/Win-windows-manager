# 已知限制

## 平台与兼容性

- 当前自动化结果来自 Windows build 26200 + AutoHotkey 2.0.30 x64。
- Windows 10、混合 DPI、多显示器负坐标、显示器热插拔未完成真机验收。
- 虚拟桌面过滤只使用 DWM cloaked 状态。其他虚拟桌面的窗口若未被标记为 cloaked，存在误纳入风险。
- 不默认提权，因此管理员权限或高完整性窗口不能被修改。
- 独占全屏检测采用保守矩形/样式判断，不代表覆盖全部游戏和特殊渲染应用。

## 窗口约束

- Win32 外部窗口的最小/最大尺寸无法总是精确获取。计划会做保守约束，并以最终 `SetWindowPos` 读回结果为准。
- 某些应用会拒绝尺寸变化或立即恢复自己的几何；执行器会记录失败并停止进一步拉扯。
- 固定尺寸而可移动的窗口只参与位置调整。
- 已有最大化窗口默认跳过；新最大化窗口只在配置允许时尝试使用 `ShowWindowAsync(SW_RESTORE)`。
- `ManualIncludeMaximized=1` 当前让最大化窗口作为固定障碍物参与布局，不会先取消最大化。

## 布局质量

- 搜索采用有限候选和有限时间预算，不保证数学全局最优。
- 应用内容实际可见面积无法精确测量，评分只使用几何近似。
- 自动和手动权重仍是可调启发式，需要真实应用组合继续调参。
- 平滑动画默认 160 ms；应用自身重绘较慢时仍可能看到卡顿。

## 状态与恢复

- Undo 历史只保存在当前进程内，脚本退出或重载后清空。
- 锁状态只保存在当前进程会话，不跨重载/重启持久化。
- 显示器移除、窗口销毁、PID 变化或目标超出当前工作区时，Undo 会安全跳过该窗口。
- 退出程序不会自动恢复此前布局。

## 交付

- `.exe` 未进行数字签名，Windows SmartScreen 可能提示未知发布者。
- 发布包必须保持 `WindowswindowsManager.exe` 与 `config.ini` 同目录。
- 当前没有 GUI 配置界面，配置通过 `config.ini` 和托盘操作完成。
- 多实例互斥行为尚未完成专项验收；调试期间曾出现一个旧调试实例与当前测试实例同时存在的情况。正式发布前应验证重复启动会只保留一个有效实例。
