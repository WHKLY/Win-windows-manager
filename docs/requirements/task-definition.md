## 产品目标

开发一个可运行、可维护、可暂停、可退出且可撤销的 Windows 浮动窗口管理程序。

核心目标是改善当前桌面的整体窗口布局，而不是只替新窗口寻找空位。程序应能：

1. 为新出现的普通顶层窗口选择可用尺寸和位置。
2. 在收益足够明显时，联合移动少量已有普通窗口。
3. 响应用户命令，对当前显示器上已存在的合格窗口进行整体重排。
4. 尊重显式锁定、正在交互的窗口、系统限制和权限边界。
5. 记录最近一次成功布局前的几何快照，并支持尽力撤销。
6. 对发生几何变化的窗口提供短时、平滑且可取消的过渡，避免生硬的瞬间跳变。

## P0 范围

### 窗口识别与保护

- 识别普通顶层窗口，并区分最小化、最大化、固定尺寸、对话框、全屏、被隐藏和系统窗口。
- 不在启动时自动重排已有窗口。
- 排除桌面、任务栏、通知、菜单、UAC、安全桌面、独占全屏和默认不适配的系统窗口。
- 支持显式锁定、正在拖动/缩放时的硬保护，以及近期手动调整时的自动模式软保护。

### 新窗口放置与自动联合优化

- 新窗口默认目标尺寸为工作区宽度的 65%、高度的 70%，安全边距为 16 px。
- 不突破应用的最小/最大尺寸和可调整能力限制。
- 自动模式同时生成“只移动新窗口”的方案 A 和“允许移动少量已有窗口”的方案 B。
- 仅当方案 B 满足硬约束、质量提升阈值和扰动限制时才采用；否则保留方案 A。
- 自动模式默认允许移动已有窗口，但默认不缩放已有窗口，单次最多移动 3 个已有窗口。

### 手动重排

- 默认快捷键：`Ctrl+Alt+Shift+L`。
- 托盘提供“重新排布当前显示器”和“重新排布所有显示器”入口。
- 当前显示器重排包含脚本启动前已存在、当前虚拟桌面、未最小化且未锁定的合格窗口。
- 手动模式默认允许在安全范围内调整已有窗口尺寸，并可提升整体布局质量。
- 所有显示器模式按显示器分别求解，默认不跨显示器搬运窗口。
- 相同输入必须得到稳定、确定的结果，避免重复触发时来回跳动。

### 撤销与状态

- 保存最近一次实际改变窗口几何的成功布局之前的快照。
- 默认快捷键：`Ctrl+Alt+Shift+Z`。
- 已关闭、HWND 已重用、显示器已移除或不再合法的窗口安全跳过，其他窗口继续尽力恢复。
- 没有实际几何变更的计划不得覆盖有效的撤销记录。

### 平滑移动

- 平滑移动是 P0 交付要求，默认启用，并允许通过配置关闭。
- 执行器将多窗口的起始几何和目标几何同步插值，使用连续性缓动，避免逐个窗口依次跳动。
- 默认建议过渡时长为 140-180 ms，单帧间隔约 16 ms；总时长必须有安全上限，不允许因动画阻塞桌面。
- 动画仅改变位置和允许范围内的尺寸；不得调用 `WinActivate`，不得改变 Z-order、置顶属性、最小化状态或焦点。
- 用户开始拖动/缩放、显示器拓扑或 DPI 发生显著变化、目标窗口失效时，应立即停止并进入既有事务的中止/恢复路径。
- 关闭平滑移动后使用同一执行器一次提交目标几何；动画和平滑关闭不能产生两套不同的布局结果。
- 最终几何必须读回验证，不能仅因动画最后一帧已调用就视为执行成功。

### 配置、快捷键与托盘

默认交互必须包含：

| 动作 | 快捷键 |
|---|---|
| 暂停/恢复自动管理 | `Ctrl+Alt+Shift+P` |
| 重新排布当前显示器 | `Ctrl+Alt+Shift+L` |
| 撤销上次布局 | `Ctrl+Alt+Shift+Z` |
| 锁定/解锁当前窗口 | `Ctrl+Alt+Shift+K` |
| 重新放置当前窗口 | `Ctrl+Alt+Shift+O` |
| 重新加载配置 | `Ctrl+Alt+Shift+R` |

托盘至少包含启用/暂停、重排当前显示器、重排所有显示器、撤销、锁定/解锁、重载配置、打开日志和退出。

### 可解释性、稳定性和兼容性

- 布局求解与 Win32 副作用分离；规划器必须可离线测试。
- 不因脚本自己的移动事件形成重入或自动回放。
- 不抢焦点、不改变 Z-order、最小化状态或置顶属性。
- 处理窗口在采集、规划、执行之间关闭或变化的情况。
- 支持负坐标、多显示器工作区和 100%/125%/150% DPI。
- 仅处理可确认处于当前虚拟桌面的窗口；不能确认时宁可跳过。
- 日志默认不得记录窗口正文、网页内容、文档文本、键盘输入或敏感窗口标题。
- 不默认提权，不静默设置开机启动。

## 非目标

- 不实现 i3/GlazeWM 式强制无缝平铺。
- 不持续监听每次移动并自动重新布局。
- 不跨虚拟桌面统一管理窗口。
- 不保证所有 UWP、Electron、游戏或工程软件都允许修改几何。
- 第一版不要求 GUI 配置界面、复杂布局动画、AI 模型或跨会话布局恢复；短时平滑几何过渡仍属于 P0。
- 不把“零重叠”作为牺牲窗口可用尺寸的理由。

## 设计与安全优先级

从高到低：

1. 安全、权限边界、窗口可操作性。
2. 显式锁定和正在进行的用户交互。
3. 避免严重遮挡并保持合理尺寸。
4. 自动模式减少扰动；手动模式提升整体布局质量。
5. 留白、对齐和视觉秩序。

显式锁定窗口可作为固定障碍物参与环境计算，但不得出现在实际变更集合中。

## 完成定义

任务只有在以下条件全部满足时才算完成：

- F01-F14 的 P0 功能均有可运行实现，或对未来需求有经用户确认的明确裁剪。
- 所有可执行的真机测试均有证据；未执行的测试保留为 `Not tested`。
- 最近一次布局可通过 Undo 恢复仍合法的窗口。
- 自动模式能按收益采用联合布局，并在收益不足时保持保守。
- 手动模式能真正重排当前显示器已有窗口，而非只处理新窗口或当前窗口。
- 暂停、重载配置、托盘操作和退出路径可用。
- 平滑移动可配置、可关闭，并且不会改变焦点或 Z-order。
- 编译后的 `.exe` 已在目标环境完成启动、暂停、配置读取和安全退出验证。
- README、配置项、测试结果和已知限制一致。
- 没有把未测试功能描述为已通过。

## 当前门禁与待确认事项

用户已明确要求执行初始提交并开始构建。初始提交、v0.1.0 MVP 构建和修复后的初步真实使用测试均已完成，后续工作以扩大真实应用、DPI、多屏和虚拟桌面覆盖为主。

以下事项未阻塞文档初始化，但应在相应阶段前确认或形成明确默认：

1. `WindowswindowsManager` 是否作为最终产品显示名称；当前作为暂定名称保留。
2. 锁状态是否只保持当前脚本会话，还是需要跨脚本重载/重启持久化；原始规格未规定，当前默认会话级。
3. 自动测试是否允许引入第三方 AHK 测试库；当前计划优先使用无额外依赖的轻量测试入口。
4. 手动“重新排布所有显示器”按原始规格进入托盘与阶段 D，但主验收仍聚焦当前显示器；如果范围要缩小，需要用户明确调整需求。
