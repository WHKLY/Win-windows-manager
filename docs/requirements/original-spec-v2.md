# Windows 智能浮动窗口编排器：AutoHotkey v2 开发任务书

> **交付本地 Coding Agent 的可执行需求与验收规范**  
> 项目暂定名：`WindowswindowsManager`  
> 规范版本：**v2.0（支持协同重排与用户主动重新布局）**  
> 目标平台：Windows 11 优先；Windows 10 尽力兼容  
> 主要技术：AutoHotkey **v2** + Win32 API  
> 文档语言：中文；代码标识符、配置项和日志字段可使用英文。

## 0. 开发指令与本次需求修订

请在本地开发一个**可运行、可维护、可关闭、可撤销**的 Windows 智能浮动窗口管理程序，使用 AHK v2。

**产品目标不是“新窗口自己找空位”，而是“让当前桌面的窗口整体呈现良好的布局”。** 打开新程序时，优先使用适中的浮动窗口尺寸；必要时**允许移动已经存在的普通窗口**，通过协同调整减少重叠、提高有效可见面积与视觉秩序。用户还能随时通过快捷键或托盘菜单，**主动要求将当前显示器的已有窗口整体重新排布**，不需要先打开新窗口。

**与 v1 规范相比，以下改动为明确要求，覆盖旧版中一切相反表述：**

1. 删除“自动模式只能移动新窗口”“任何情况下都不移动旧窗口”的限制。
2. 新窗口出现后允许对**新窗口 + 一部分已有窗口**做联合布局。是否移动旧窗口由布局质量提升和用户保护约束决定，不应无条件全部移动。
3. 新增**手动全局重排（P0）**：对当前显示器的所有合格窗口统一优化位置，允许适当改变其尺寸；用户可以反复主动触发。
4. 新增**撤销上次重排（P0）**：记录操作前几何快照，支持一键恢复，尤其用于全局布局效果不满意时。
5. 尊重用户意图不是“旧窗口永远不动”，而是：保护明确锁定的窗口、正在拖动的窗口、受系统限制的窗口；自动模式较温和，用户主动重排可以更积极。
6. 不做持续强制平铺。仍采用**自由浮动、多窗口协同优化**：允许适度遮挡与自然错位，避免所有窗口被强塞进预设网格。

请依据本文件直接编写源代码、默认配置、README 和测试内容；不要只输出讨论、伪代码或计划。按阶段交付可运行的 MVP，并明确记录测试证据。若开发环境无法运行 Windows / AHK，则完成静态实现、能完成的静态检查和测试规划，标记真机测试为 **Not tested**，不得假称运行验证成功。

## 1. 功能要求

### 1.1 必须实现（P0）

| ID | 要求 | 验收要点 |
|---|---|---|
| F01 | 识别新创建/新显示的普通顶层窗口 | 不把焦点切换、最小化恢复、临时弹窗一概当作新窗口 |
| F02 | 新窗口采用合理的默认浮动尺寸 | 仅限符合条件且允许缩放的窗口；遵守系统与应用约束 |
| F03 | 空工作区优先居中 | 保证在工作区内、标题栏可操作 |
| F04 | 多窗口布局优化 | 考虑窗口之间的重叠、可见面积、间距、中心倾向、移动代价 |
| F05 | 自动模式可以移动已有窗口 | 新窗口出现时，能够选择“只移动新窗口”或“联合移动已有窗口”，并择优实施 |
| F06 | 手动重新排布 | 用户通过可配置快捷键或托盘菜单主动重排当前显示器所有合格窗口，不依赖新窗口事件 |
| F07 | 自动与手动策略不同 | 自动模式保守、避免打扰；手动模式偏重整体显示效果，允许更大范围的位置/尺寸调整 |
| F08 | 一键撤销 | 对最近一次成功应用的多窗口布局保存快照并恢复；对已关闭/不兼容窗口安全跳过 |
| F09 | 用户锁定与交互保护 | 能固定特定窗口；用户正在操作、近期主动调整、特殊窗口不应被粗暴接管 |
| F10 | 正确过滤不适合管理的窗口 | 系统桌面、任务栏、通知、菜单、UAC、游戏独占全屏、模态对话框等默认排除 |
| F11 | 多显示器正确性 | 以当前/目标显示器工作区布局；支持负坐标、不同 DPI；默认不跨屏迁移其他窗口 |
| F12 | 可配置、可暂停、可退出 | 支持调整比例、质量权重、重排范围、排除表、快捷键和自动启动 |
| F13 | 结果稳定、可控 | 不反复跳动、不抢焦点、不改 Z-order；窗口关闭/状态变化时安全停止；避免高频轮询 |
| F14 | 可解释和可测试 | 几何求解模块与 Windows 副作用分离；记录为何移动某窗口或为何跳过 |

### 1.2 非目标 / 第一版不强求

- 不实现 i3 / GlazeWM 式**强制无缝平铺**；不要求窗口必须充满屏幕或完全不重叠。
- 不持续监听每一次鼠标移动来自动重新计算布局。**默认只由新窗口事件或用户明确指令触发布局**。
- 不跨 Windows 虚拟桌面统一重排；只考虑当前可操作虚拟桌面的窗口。
- 不要求所有 Win32、UWP、Electron、游戏及工程软件都能被强制更改几何；必须优雅处理不支持的情况。
- 不强求第一版包含 GUI 配置界面、窗口布局动画、AI 模型、复杂物理仿真、跨会话的历史布局恢复。
- 不假设 macOS 有一个固定且公开的“智能放置算法”；以本规范验收场景为准。

### 1.3 设计优先级

全局硬约束（安全、可操作性、窗口权限、用户显式锁定）优先于所有美观目标。可行方案中：

1. 保持窗口可操作（至少标题栏和必要交互区域可达），不丢失窗口；
2. 优先避免严重重叠、改善重要内容的有效可见面积；
3. 尽量保留合适尺寸、不过度缩小窗口；
4. 自动模式尽量减少既有窗口扰动，手动模式更重视整体布局质量；
5. 以恰当留白、适度对齐、视觉重心等优化观感。

“减少重叠”并不是唯一目标：为了零重叠把所有窗口缩成极小方块，也算失败。

## 2. 默认交互与布局策略

### 2.1 新窗口初始大小

以所选显示器的**工作区**（扣除任务栏）为基准，推荐新普通窗口的默认尺寸：

- 目标宽度：工作区宽度的 `0.65`；
- 目标高度：工作区高度的 `0.70`；
- 安全边距：`16 px`（注意 DPI 与坐标一致性）；
- 不突破应用报告或实际执行的最小/最大尺寸；
- 如果窗口不可调整大小，只参与**允许范围内的位置优化**；如果窗口不适合被管理，则跳过。

这个比例是**初始建议**，而非对所有应用强制相同尺寸。对于资源管理器、浏览器、终端、IDE 等可提供按进程覆盖策略。已有窗口默认优先保留当前尺寸；**手动全局重排可在限制内改变其尺寸**。

### 2.2 自动模式：新窗口引发的协同重排

**默认启用** `AutoMoveExistingWindows=1`，但不代表每次打开程序都移动所有旧窗口。

当新普通窗口稳定出现：

1. 获取目标显示器当前合格窗口、原始位置、尺寸、可变更能力和保护状态。
2. 计算 `方案 A`：仅改变新窗口的位置与适用的默认尺寸；旧窗口不动。
3. 计算 `方案 B`：新窗口与允许调整的一部分旧窗口联合优化。默认允许旧窗口**移动**，自动模式默认**不缩放旧窗口**。
4. 如果 `方案 B` 相比 `方案 A` 带来**足够显著**的质量提升，且旧窗口变动量、用户交互状态等符合自动模式限制，则采用 `方案 B`；否则采用 `方案 A`。
5. 事务式应用方案、校验位置并保存撤销快照。处理完成后释放控制权，**不因为窗口切换前台就再布局**。

建议默认约束：一次自动布局最多移动 `3` 个已有窗口（可配置）；移动旧窗口须有明确收益；自动放置期间若用户开始拖动，取消或重新检查计划；最近 `5000 ms` 内由用户手动移动/缩放过的窗口，默认作为**临时软锚点**优先保留。不要仅为了微小分数改进移动旧窗口。

**关键场景：** 左侧有两个窗口，新开第三个窗口，右侧留白不足；若轻微移动左侧两个窗口可形成明显更合理的三窗口布局，则**应该允许自动移动那两个旧窗口**，而不是拘泥于只动第三个。

### 2.3 手动模式：用户主动“重新排布全部窗口”

新增显式命令 `ReflowCurrentMonitor()`（名称可自定），默认快捷键 `Ctrl+Alt+Shift+L`，同时提供托盘菜单项 **“重新排布当前显示器”**。

执行原则：

- 将**当前显示器、当前虚拟桌面、未最小化、未显式锁定**的合格普通窗口组成优化集合；**包括早于脚本启动时打开的窗口**。
- 允许移动全部合格窗口；默认允许在合理范围内**调整已有窗口尺寸**，以获取明显更好的整体效果。
- 不因为某个窗口不是“新窗口”就把它排除。
- 手动模式的移动代价权重小于自动模式，允许更积极地优化整体布局，但不能改变显式锁定窗口、不可调整尺寸约束和系统保护边界。
- 当前活动窗口可以参与重排，但应赋予合适的可用性/可见性权重，避免把它深度遮挡。
- 重排后保持正常自由浮动模式；用户依然可以拖拽、缩放、最大化任意窗口。
- 支持重复触发；若窗口集合与几何基本未变，结果应确定、稳定，**不得每按一次都在几种布局之间来回跳动**。
- 如果只存在一个可管理窗口，优先居中并采用合理尺寸；如果存在多个，寻找整体质量最高的可行布局。

**范围规定：** 手动默认仅整理**当前活动窗口所在显示器**，不悄悄打乱副屏。可通过独立菜单项/可配置命令 `ReflowAllMonitors()` 对各显示器**分别**执行重排；默认不在显示器之间搬运窗口。多屏之间跨屏迁移属于可选 P1 功能，必须有单独开关。

### 2.4 用户手动调整与“锁定窗口”

将用户意图分为三个层次，不可混为一谈：

1. **显式锁定（硬约束）**：由快捷键/菜单锁定指定窗口。该窗口不会被自动或手动重排移动/缩放；可以作为其他窗口布局时的固定障碍物。用户可解锁。
2. **正在交互（瞬时硬约束）**：检测到用户正在拖动、缩放、最大化窗口，任何布局计划都不得覆盖这次操作。
3. **近期用户手动调整（临时软约束）**：自动模式尽量避免动它；用户**主动**要求全局重排时，可以改变它，除非已显式锁定。

不要将一次手动拖拽永久等同于“锁定”。用户主动全局重排的优先级应高于“最近动过”的软约束。

最小化窗口默认不参与当前布局；已有最大化窗口默认**不解除最大化，也不移动/缩放**，但应按其工作区占用情况处理其他窗口（可在配置中排除其作为障碍物）。手动重排是否允许包含最大化窗口，必须有单独显式选项，默认关闭。新窗口若初始最大化，可按旧规范的可管理资格规则选择恢复后布局。

### 2.5 默认快捷键及托盘功能

| 动作 | 默认快捷键 | 说明 |
|---|---|---|
| 暂停/恢复自动管理 | `Ctrl+Alt+Shift+P` | 停止/恢复后续自动新窗口重排；手动命令是否仍可用由设置决定，默认可用 |
| **重新排布当前显示器** | **`Ctrl+Alt+Shift+L`** | **核心新增功能：整理当前屏幕所有合格窗口** |
| 撤销上次布局 | `Ctrl+Alt+Shift+Z` | 恢复上一次成功布局前的窗口几何快照 |
| 锁定/解锁当前窗口 | `Ctrl+Alt+Shift+K` | 显式固定当前活动窗口，切换锁定状态 |
| 重新放置当前窗口 | `Ctrl+Alt+Shift+O` | 单窗口手动放置命令，区别于全局重排 |
| 重新加载配置 | `Ctrl+Alt+Shift+R` | 重读配置与可用快捷键 |

托盘至少提供：启用/暂停自动模式、**重新排布当前显示器、重新排布所有显示器、撤销、锁定/解锁当前窗口**、重载配置、打开日志、退出。若热键冲突允许改键。单窗口命令与全局重排不可共用而含糊处理。

### 2.6 典型场景与期望行为

- **空桌面打开 Terminal**：默认缩成合适的浮动窗口并居中。
- **一个窗口已经覆盖屏幕左大半区域，再打开浏览器**：先判断只移动浏览器能否良好显示；如调整已有窗口能显著减少遮挡，则可同时移动它。
- **已有两个窗口，再打开第三个**：允许三个窗口协同变更，旧窗口被移动是可接受乃至预期结果，而非测试失败。
- **桌面已有五个杂乱窗口，用户按 `Ctrl+Alt+Shift+L`**：无须创建新窗口，所有符合条件的未锁定窗口重新排布，必要时调整大小。
- **用户不喜欢结果，按撤销快捷键**：尽可能恢复上一布局；已销毁/状态发生变化的窗口不能阻塞其他窗口的恢复。
- **用户固定了视频播放窗口**：无论新窗口到来或手动重排，都不得移动它；其他窗口在其周围优化。
- **用户拖拽 VS Code 后立刻打开新窗口**：自动模式尽量保留 VS Code 刚刚设置的位置；主动全局重排可以重新移动它。
- **手动排布后继续正常工作**：程序不会持续追着每次拖拽重新改变用户布局。

## 3. 推荐技术架构与 Windows 约束

### 3.1 事件监听

首选 Windows `SetWinEventHook` 配合 AHK v2 `DllCall`、`CallbackCreate`，使用 `WINEVENT_OUTOFCONTEXT`。事件回调只进行最小初筛并入队，求解放到定时器/串行任务队列中，不阻塞回调。

| 事件 | 常量/值 | 用途 |
|---|---|---|
| 窗口创建 | `EVENT_OBJECT_CREATE` / `0x8000` | 标记可能的新顶层窗口 |
| 窗口显示 | `EVENT_OBJECT_SHOW` / `0x8002` | 检测候选窗口可管理性 |
| 前台切换 | `EVENT_SYSTEM_FOREGROUND` / `0x0003` | 保存焦点优先级，不作为唯一新建判断 |
| 窗口销毁 | `EVENT_OBJECT_DESTROY` / `0x8001` | 状态清理、锁定状态和快照失效处理 |
| 用户开始移动缩放 | `EVENT_SYSTEM_MOVESIZESTART` / `0x000A` | 交互保护 |
| 用户结束移动缩放 | `EVENT_SYSTEM_MOVESIZEEND` / `0x000B` | 更新时间戳、软锚点状态 |

实现要求：

- 校验 `idObject == OBJID_WINDOW (0)`、`idChild == CHILDID_SELF (0)`，并通过顶层窗口条件进一步筛选。
- 脚本启动时建立已存在窗口集合：**不在启动时自动重排**。注意这并不限制这些窗口在**以后新窗口触发协同布局**或**用户主动重排**时成为参与者。
- 新窗口初次显示后推荐去抖等待 `150–400ms`（最大约 `1000ms`），检查它是否自行改变几何、被用户操作、或已关闭。
- 防止 HWND 重用：校验句柄有效性、PID、可获取的身份元数据；销毁后及时清理，不只维护永久 `hwnd` 集合。
- 由脚本执行 `WinMove` / `SetWindowPos` 产生的变化必须识别为内部操作，禁止事件反馈触发新的布局递归。
- hook 句柄及回调对象保持存活，退出时释放；如果部分应用监听不到，可加低频校验而非高频扫描。
- 默认**不**因为 `MOVESIZEEND` 自动全局重排；它主要用于用户意图保护。重排触发条件必须明确、可配置。

### 3.2 窗口识别与可变更能力分类

不要只返回 `true / false`，应对每个窗口得到类似下列结构：

```text
WindowInfo:
  identity(hwnd, pid, class, process)
  rect, monitorId, desktopEligibility
  isVisible, isMinimized, isMaximized, isCloaked
  isNormalTopLevel, isOwnedDialog, isFullscreen
  canMove, canResize, minSize, maxSize
  explicitlyLocked, isUserInteracting, recentlyManuallyChanged
  isForeground, isTopmost, priority
```

参考过滤条件：`IsWindowVisible`、`GetAncestor`、`GetWindow(GW_OWNER)`、窗口样式 (`WS_CHILD`, `WS_EX_TOOLWINDOW` 等)、`DwmGetWindowAttribute(DWMWA_CLOAKED)`、可调整边框、应用排除规则等。不要仅根据标题是否为空判定。处理模态窗口、文件选择器、菜单、通知、桌面/任务栏/UAC/安全桌面时，应默认跳过或保持原位。

为最大化窗、固定尺寸窗、用户锁定窗设置不同能力：

- **Movable & Resizable**：可参与位置和允许范围内的尺寸调整。
- **Movable Only**：可以移动但不可改变尺寸。
- **Fixed Anchor**：不可移动也不可缩放，但可用其位置作为布局障碍物。
- **Excluded**：不参与管理，且通常不计入障碍物（如桌面/普通系统菜单）；必要时为特定覆盖层设置计入障碍物的配置。

对管理员权限、高完整性、系统保护或应用拒绝修改的窗口安全跳过，切勿绕过 Windows 权限边界。**默认不提升管理员权限。**

### 3.3 显示器与虚拟桌面

- 优先采用新窗口最初所处显示器；若无效，回退到事件发生时的活动窗口显示器，再到鼠标所在显示器，最后主屏。
- 手动重排以**触发快捷键时活动窗口所属显示器**为默认范围；活动窗口缺失时可回退鼠标显示器。
- 使用 `MonitorGetWorkArea` 或对应 Win32 API 获取各屏可用区域；支持主屏左侧副屏带来的负坐标。
- 统一 `WinGetPos`、`SetWindowPos`、DWM 边界与工作区的 DPI / 坐标策略，验证 100%、125%、150% 缩放组合。
- 仅处理当前可用虚拟桌面的窗口；`DWM cloaked` 判断可能不足以覆盖所有场景，如需准确判定可研究 `IVirtualDesktopManager::IsWindowOnCurrentVirtualDesktop`，遇到未能可靠确认的窗口宁可谨慎跳过，不能跨虚拟桌面误移动。
- 默认不自动跨物理显示器迁移旧窗口。全显示器重排是**逐屏独立求解**，不是把所有屏幕合并成一个大画布。

### 3.4 架构边界与组件职责

建议解耦以下模块：

```text
WinEventListener
  -> WindowRegistry / WindowClassifier
  -> TriggerController (NewWindow / ManualReflow / PlaceOne / Undo)
  -> SnapshotCollector (Monitor, Windows, Constraints, Locks)
  -> LayoutPlanner (候选、评分、搜索；不直接调用 Win32)
  -> LayoutExecutor (预检查、批量移动、读回、失败处理)
  -> History / Undo
  -> Config / Tray / Hotkeys / Logger
```

**重要：布局算法不应直接 `WinMove`。** 它应接收可序列化窗口几何及约束，返回目标布局和评分，支持离线单测及不同策略对比。

## 4. 多窗口布局优化算法

### 4.1 输入与输出

输入：

- 显示器工作区矩形 `W`、边距 `margin`、DPI 策略；
- 当前可见合格窗口集合 `R={r1,...,rn}`，包括窗口当前位置、尺寸、最小/最大尺寸、可移动/可缩放能力；
- 每个窗口的权重：是否新窗口、焦点窗口、显式锁定、近期用户手动调整、应用偏好；
- `mode ∈ {auto_new, manual_reflow, manual_one}`；
- 配置上限：单次自动移动已有窗口数、尺寸变化范围、可接受最小尺寸等。

输出：

```text
LayoutPlan:
  targets: {windowIdentity -> (x,y,width,height)}
  changedWindows: [...]  # 只包含实际需改动的窗口
  scoreBefore, scoreAfter
  mode, monitorId
  reasons / skippedWindows
  snapshotForUndo
```

显式锁定窗口等固定障碍物可以进入规划器的环境输入，但不得出现在 `changedWindows` 中。

### 4.2 硬约束

1. 目标窗口的可操作区域必须留在所属显示器工作区内；不可把标题栏整体移出屏幕。工作区比某固定窗口更小时需制定安全降级策略。
2. 不违反窗口不可缩放、最小/最大尺寸、显式锁定及权限约束。
3. 当前用户正在拖动/调整的窗口不得在本次事务中移动。
4. 默认不更改显示器归属、Z-order、置顶属性、最小化状态或键盘焦点。
5. 自动模式遵守旧窗口移动数量/扰动上限；手动模式可取消该上限。
6. 不得通过隐藏窗口、最小化窗口或将其置于其他窗口背后来“提高优化得分”。

### 4.3 评分目标

对完整布局 `L` 使用可解释的代价函数（允许使用分层排序与加权评分的混合）：

```text
J(L) = w_overlap * OverlapCost(L)
     + w_focus   * ImportantWindowOcclusion(L)
     + w_size    * SizeDeviationCost(L)
     + w_move    * ExistingWindowMovementCost(L)
     + w_edge    * InvalidOrPoorVisibilityCost(L)
     + w_space   * PoorSpacingAndAlignmentCost(L)
     + w_center  * CenterBiasCost(L)
```

其中：

- `OverlapCost`：窗口两两矩形相交面积，按工作区面积归一化；可对多层遮挡设置惩罚，避免简单累加误导。
- `ImportantWindowOcclusion`：当前活动窗口与高优先级窗口被遮挡的代价；不试图模拟精确内容可见度。
- `SizeDeviationCost`：相对合适尺寸的缩小量、长宽比畸变、窗口太窄导致不可用；不能仅因减小窗口面积就得到“最佳”解。
- `ExistingWindowMovementCost`：旧窗口位移和尺寸改变；**自动模式权重高**，**手动模式权重低**。可针对最近手动调整的窗口加罚。
- `InvalidOrPoorVisibilityCost`：超出屏幕、标题栏不可达等应设为硬性非法或极大惩罚。
- `PoorSpacingAndAlignmentCost`：适度的边距、窗口间距、重心与一致性；禁止将所有窗口强制吸附到固定网格作为唯一解。
- `CenterBiasCost`：空闲或候选等价时偏向中央，但优先级低于严重重叠和可操作性。

分项要进行合理归一化，不能把像素距离、面积、相对尺寸直接加在一起而不缩放。实现应记录各项指标以便解释与调参。

**新窗口自动决策必须比较至少两种基线：**

- `A: NewWindowOnly`：只放置新窗口，旧窗口维持原样；
- `B: CooperativeReflow`：允许移动一部分已有窗口，与新窗口联合优化。

只有当 `B` 达到配置的质量提升阈值、旧窗口干扰约束以及所有硬约束时，才实施 `B`。否则实施 `A`。应记录选择理由。若原布局已经不错，保留现状是可接受的正确解。

手动重排直接对当前合格窗口整体优化，但保留旧布局作为候选基线。如果没有明显改善，可不移动，提示“当前布局已较优”。

### 4.4 候选生成和搜索（务实、确定性）

不建议一开始就上全局黑箱最优化。建议分级策略：

**Level 1：纯几何基础能力**

- 矩形相交面积、边界裁剪、工作区内可放置范围、尺寸可行性。
- 候选位置：原位、中心、边角、四边中点、网格样本、贴近其他窗口四边的位置、按窗口边缘构造的对齐/间隙位置。
- 避免所有像素逐个穷举；矩形接触/重叠等要有单元测试。

**Level 2：联合优化 MVP（P0）**

1. 按焦点/固定程度、面积或稳定规则排列待处理窗口；
2. 对每个可移动窗口生成合法位置，必要时生成少量可行尺寸候选；
3. 以完整布局的目标分数逐个优化（贪心 + 多轮坐标下降）；
4. 加入**原位候选**与**重排历史**，避免为了微小收益扰动窗口；
5. 可采用有限 beam search / 多初始点来降低局部最优风险，但必须限制计算量；
6. 若迭代后收益低于阈值，则回退到更保守的计划；
7. 以固定次序打破并列，确保相同输入输出稳定。

**Level 3：后续 P1 增强**

- 更自由的候选采样、布局多样性、重要窗口保持更大、场景/应用优先级、跨显示器可选重排、全局更优搜索。

窗口数通常不大，MVP 应在有限候选和迭代预算内完成。应有**计算超时/求解退化保护**：超时返回当前最好的合法方案，不阻塞 AHK 事件处理。对过多窗口不要求最优数学解，但不得死循环。

### 4.5 自动模式和手动模式的参数区分

| 维度 | 自动：新窗口触发 | 手动：全局重排 |
|---|---|---|
| 作用范围 | 新窗口 + 少量可调整旧窗口 | 当前屏幕所有合格、未锁定窗口 |
| 是否允许移动已有窗口 | **允许，默认开启** | **允许，核心功能** |
| 是否允许缩放已有窗口 | 默认关闭（可配置） | 默认开启，但受尺寸约束 |
| 移动代价 | 高 | 低 |
| 最近人工调整窗口 | 尽量避免移动 | 可移动，除非显式锁定 |
| 最大移动旧窗口数量 | 默认建议 3（可配置） | 无固定数目上限 |
| 触发时机 | 新窗口稳定显示 | 用户明确执行命令 |
| 是否改变窗口焦点/Z-order | 否 | 否 |
| 是否支持撤销 | 是 | 是 |

## 5. 安全执行、多窗口事务与撤销

### 5.1 生命周期

```text
TRIGGERED (NEW_WINDOW / MANUAL_REFLOW / MANUAL_ONE)
  -> SNAPSHOT (收集窗口 / 显示器 / 锁定 / 操作状态)
  -> FILTERED / PLAN (计算候选，比较质量)
  -> PRECHECK (复核身份、交互、显示器、权限、约束)
  -> APPLY (在尽可能短的批次内调整目标窗口)
  -> VERIFY (读回每个窗口的位置尺寸)
  -> COMMIT (保存可撤销快照；结束本次事务)
       or ROLLBACK/BEST_EFFORT_RECOVERY (部分失败时可恢复)
```

### 5.2 执行要求

- 在执行布局前**完整捕获快照**：窗口身份（含 PID / 防 HWND 重用信息）、矩形、显示器、原最大化状态等必要元数据；只对本次确实发生变化的窗口提交动作。
- 执行期间暂停本脚本对新窗口事件的重复布局；通过 `isApplyingLayout` / 事务 ID 等区分脚本移动和用户手动移动。
- 推荐研究 `BeginDeferWindowPos` / `DeferWindowPos` / `EndDeferWindowPos` 进行一批窗口更新，或使用有严格边界的串行 `SetWindowPos` / `WinMove` 实现。**不要把批量 API 当成绝对原子事务**：仍必须读回验证、处理失败与目标窗口消失。
- 使用适当标志避免激活窗口或修改 Z-order（例如 Win32 `SWP_NOACTIVATE`、`SWP_NOZORDER`；以实际调用场景核对）。不调用 `WinActivate` 或 `SetForegroundWindow` 作为常规移动步骤。
- 布局计划与执行之间，如有目标窗口被关闭、用户开始拖动、显示器拔插或 DPI/工作区显著变化，应放弃旧计划并安全重算或跳过。
- 遇到应用拒绝调整、应用主动改回窗口几何、或权限不足，限制重试次数，记录原因并将其视为固定障碍物或跳过；**不得反复拉扯窗口**。
- 切忌在运行中的人工交互上叠加持续布局：窗口位置变化不是自动启动下一次布局的充分条件。

### 5.3 撤销与恢复（P0）

- 保存**最近一次实际改变了窗口几何的成功布局**之前的快照；默认至少支持一级 Undo，允许扩展成多级历史（P1）。
- 用户按 `Ctrl+Alt+Shift+Z` 或托盘点击“撤销上次布局”时：重新检查窗口身份、可见性、权限和正在交互状态，并恢复仍合法的窗口。
- 原窗口已经关闭、HWND 已重用、显示器被拔掉、窗口变得不可移动/缩放时，对该窗口**安全跳过**，其他可恢复窗口继续处理；给出简洁报告。
- 撤销动作也必须避免抢焦点/改 Z-order；撤销完成不应立即被自动布局“再次纠正”。
- 记录 Undo 的操作范围及窗口数；未实际应用几何变更的计划不得覆盖上一条有效 Undo 记录。
- 默认 Undo 是针对**脚本最后一次布局操作**，不是 Windows 系统级的任意窗口移动历史；README 必须说明。

### 5.4 暂停、恢复与退出

- 暂停自动管理不应强制恢复旧布局，只阻止后续自动触发。用户可选择仍然使用手动重排/撤销。
- 退出释放 hooks/回调/定时器，不保留不能撤销的系统配置；不自动还原已经调整的窗口（除非用户主动 Undo）。
- 开机启动必须由用户显式开启且可撤销。禁止未经同意写注册表自启或绕过权限保护。

## 8. 验收测试：必须逐项记录 Passed / Failed / Not tested

最低真机环境：Windows 11 + AHK v2；建议覆盖 Windows Terminal、文件资源管理器、浏览器、VS Code。对未安装的应用可换同类产品并记录。若无 Windows GUI 环境，绝不冒充真机已测试。

| ID | 测试场景 | 通过标准 |
|---|---|---|
| T01 | 启动管理器时已开 3 个窗口 | 启动本身不触发意外重排；此后它们可参与新窗口协同布局和手动重排 |
| T02 | 空桌面打开单个普通窗口 | 以非最大化、合理大小基本居中呈现 |
| T03 | 左侧已有窗口，右侧可容纳新窗口 | 自动选择低重叠的位置，不盲目堆在中央 |
| **T04** | **已有两个窗口，再开第三个，旧窗口小幅移动可显著改善布局** | **自动模式允许移动已有窗口，三者形成更好布局；旧窗口移动不是错误** |
| T05 | 已有布局合理，新窗口能单独放置 | 自动模式不为微小评分收益无端挪动所有旧窗口 |
| **T06** | **已有 5 个杂乱窗口，不新建程序直接按全局重排快捷键** | **多个已有窗口的位置得到协同优化；需要时可在约束下调整大小** |
| T07 | 手动重排两次，窗口集合不变 | 结果稳定，不循环跳动、不随机互换窗口 |
| **T08** | **对上次自动/手动布局执行 Undo** | **合格窗口恢复原几何，恢复过程不触发自动再次重排** |
| T09 | 关闭其中一窗后 Undo | 剩余仍合法窗口尽可能恢复，关闭窗口安全跳过，无崩溃 |
| T10 | 锁定当前窗口，打开新窗口，执行手动重排 | 锁定窗口不变，其余窗口绕它优化；解锁后可参与下一次重排 |
| T11 | 用户刚拖动窗口，立即打开新应用 | 自动模式尊重近期操作；正在拖动的窗口绝不被覆盖 |
| T12 | 用户主动要求全局重排近期拖动的未锁定窗口 | 可参与重排；不被误当成永久锁定 |
| T13 | 最小化后恢复旧窗口、普通焦点切换 | 不误触发新窗口自动布局；仍可通过手动命令重排 |
| T14 | 文件选择框、系统菜单、通知、UAC 等 | 不误判成普通应用窗口，不无端挪动或缩放 |
| T15 | 全屏游戏、特殊渲染窗口 | 不干涉全屏，不导致前台切换或输入焦点丢失 |
| T16 | 新普通窗口以最大化初始显示 | 符合资格时可按配置恢复并布局；不符合资格时安全跳过 |
| T17 | 暂停自动模式后新开窗口 | 不进行自动布局；用户手动命令仍按设计可用；恢复后新窗重新生效 |
| T18 | 一次打开至少 10 个窗口 / 触发事件风暴 | 无重入循环、明显卡死、高 CPU 或大量窗口闪动 |
| T19 | 副屏位于主屏左侧（负坐标），分别重排 | 每个屏幕窗口保持在各自工作区，默认不跨显示器迁移 |
| T20 | 100% 与 150% DPI / 不同分辨率 | 工作区和位置计算正确，不超出屏幕 |
| T21 | 有固定尺寸窗口和不可管理窗口 | 保持尺寸/跳过或当成固定障碍物，其余窗口照常优化 |
| T22 | 某应用拒绝位置调整或主动恢复几何 | 有限重试，日志说明，不反复拉扯、不影响其他窗口 |
| T23 | 手动重排时鼠标正在拖动窗口 | 等待交互结束或安全中止；不能与用户抢控制权 |
| T24 | 窗口已最小化、属于其他虚拟桌面或被 cloaked | 不被错误搬到当前屏幕 |
| T25 | 退出程序及开机启动关闭 | hooks/快捷键释放；后续应用遵循 Windows 默认行为，取消自启路径明确 |
| T26 | 当前屏幕窗口过多，不可能完全不重叠 | 保持可操作性和合理尺寸，给出较优布局，不极端缩小所有窗口 |

### 性能、稳定与可用性要求

- 闲置时低资源占用；目标是常见机器上空闲 CPU 约 `1%` 或以下（仅建议，按真机记录）。
- 单新窗口布局通常在显示后约 `0.2–1.0 s` 内完成；全局重排可略慢，但应具备有限计算预算，不能卡死桌面。
- 每次布局最多有限数量的有效位置/尺寸调整，不允许“移动—被应用恢复—再移动”的无限循环。
- 用户按快捷键后可预测地生效；托盘支持暂停/退出，发生严重异常应优先安全降级。
- 任何真实布局更改均应可以通过最近一次 Undo 恢复可恢复的窗口。
- 默认日志不得包含浏览器网页内容、文档文本、敏感窗口标题或键盘输入；保留 PID/进程名和脱敏几何足以调试。

**必须同时评价“布局质量”和“干扰程度”。** 不得把“自动模式一次移动全部窗口”或“将全部窗口缩至难以使用”判作成功。建议记录布局前后重叠面积、平均可见面积估计、参与窗口数、原有窗口移动数量/平均位移、求解耗时与失败数量。

## 9. 分阶段实施顺序

### 阶段 A：基础运行、窗口识别与 DryRun

- 配置加载、hook 生命周期、窗口身份/过滤、显示器定位、托盘、暂停/退出、调试日志。
- 将已存在窗口纳入注册表/规划候选，但**启动不自动移动任何窗口**。
- 提供 `DryRun`：可生成计划及评分，不调用真正的窗口移动 API。

**完成标准**：识别正常主窗口与应跳过窗口；事件无明显重复处理；可安全退出。

### 阶段 B：单窗口放置与基础几何

- 实现原位、居中、边界候选；新窗口合适尺寸、工作区计算、读取并验证 WinMove 结果。
- 支持单窗口手动命令和基础锁定分类。

**完成标准**：T01、T02、T03、T13、T16 基本通过，几何函数单测通过。

### 阶段 C：**自动联合优化（新 P0）**

- 同一工作区收集既有窗口与新窗口，生成 A（只动新窗）和 B（协同移动已有窗口）两方案。
- 完成质量比较、扰动阈值、近期用户调整保护、内部移动事件隔离。
- 自动模式默认支持移动已有窗口；过度改动时能选择退回 A 方案。

**完成标准**：重点通过 **T04、T05、T11、T18、T26**，且旧窗口可被正确移动并得到可解释的布局收益。

### 阶段 D：**手动全局重排、锁定、Undo（新 P0）**

- 加入 `ReflowCurrentMonitor`、逐屏 `ReflowAllMonitors`、热键与托盘菜单。
- 允许手动模式在安全范围内缩放已有窗口；显式锁定窗口必须保持原位。
- 增加执行前快照、批量调整校验、一级 Undo 与部分失败的安全恢复。

**完成标准**：重点通过 **T06、T07、T08、T09、T10、T12、T23**。不得仅实现“按一下移动当前窗口”来充当全局重排。

### 阶段 E：多屏、DPI、应用兼容与交付

- 检查多显示器负坐标、DPI、虚拟桌面排除、权限差异、工程软件等场景。
- 完成适当的异常日志与 README；真机记录第 8 节所有能执行的测试；未测试项如实标注。

**完成标准**：所有 P0 功能具备可运行代码和可复现验证；无法兼容的应用有解释和降级行为。

每阶段应提交简短变更摘要、如何实际运行/复现、哪些测试通过或失败。遇到困难优先保持可运行的上阶段版本，而不是引入未验证的大型依赖。

## 10. 代码质量要求与禁止事项

- 严格使用 `#Requires AutoHotkey v2.0`；不可混入 AHK v1 语法。
- 对外部 HWND 做生命周期和异常保护；窗口可在检测、规划、执行之间被关闭或重建。
- GUI 事件处理、hooks 回调不要执行长时间搜索或 `Sleep`。耗时工作交由可控队列/定时器，并防止 AHK 的重入问题。
- 不默认提权、不屏蔽 Windows Defender、不键盘记录、不采集窗口正文；不修改其他应用自身配置文件。
- **允许并要求**在合适场景移动已有普通窗口；禁止的是**无条件大范围重排**、频繁干预人工调整、把系统保护窗口强行纳入。
- 不以 `WinActivate` 强制激活旧窗口，也不通过修改 Z-order 或隐藏窗口假装优化了可见面积。
- 新窗口触发与手动触发的**默认作用范围和扰动权重必须分开**。
- 手动全局命令必须对“已存在窗口集合”执行联合布局，不得只是循环给各窗口单独居中。
- 严格验证应用窗口尺寸约束，禁止为了零重叠把窗口缩得不可用。
- 必须有最少一级 Undo 且能处理部分窗口不可恢复的情况；Undo 后应暂时抑制同一布局自动回放。
- 配置自启须由用户同意且可取消；不能静默持久化后台运行。
